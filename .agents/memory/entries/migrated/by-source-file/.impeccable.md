# DB Pro Design Context

## Users
Database developers and analysts working for long sessions in a native desktop IDE. They inspect schemas, write queries, browse result sets, and make controlled data edits.

## Use Cases
- Navigate connections, schemas, tables, views, and routines.
- Read and filter dense tabular data without losing context.
- Run queries and inspect SQL/results with clear status and recovery states.
- Edit data through compact, keyboard-friendly controls.

## Brand Personality
Calm, technical, precise. The interface should feel like a trusted database workstation: dense enough for expert workflows, quiet enough for long sessions, and explicit about state.

## Aesthetic Direction
Dark database workstation inspired by shadcn Primitives & Controls: charcoal/navy surfaces, crisp 1px borders, compact controls, restrained blue accent, small radii, Lucide iconography, and no decorative gradients or glow. The screenshot reference is a dense IDE surface, not a marketing dashboard.

## Design Principles
1. Surface hierarchy comes from restrained value shifts and borders, not cards stacked on cards.
2. Controls are compact, labeled, keyboard-friendly, and show clear hover/focus/active states.
3. Data density is intentional: tight rows, aligned columns, monospace where it improves scanning.
4. Semantic colors are reserved for state and action; selection should not overpower the data.
5. Every visual decision is a `DbProTheme` or token decision, never a view-local color constant.
