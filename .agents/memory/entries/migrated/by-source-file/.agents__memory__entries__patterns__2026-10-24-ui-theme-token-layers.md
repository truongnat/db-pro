# Tóm tắt

Mọi quyết định visual trong shell native phải đi qua **token** (`SPACE_*`, `STROKE_*`, semantic roles light/dark), không đặt literal trong view hoặc component trừ geometry paint có comment calibration.

## Khi nào áp dụng

- Sửa/audit `crates/ui/src/components/**` và view dùng `DbProTheme`.
- Đánh giá space, border, color light/dark consistency.

## Bối cảnh và bằng chứng

- **Đã xác nhận:** Layer 1 primitive (scale + palette private), layer 2 semantic (explicit light/dark), layer 3 component; `DbProTheme` là facade tương thích.

## Nguyên nhân gốc / quyết định

Hardcode `Color32`, margin số lẻ, stroke 1.0 rải rác → drift giữa component và không switch theme đúng role.

## Cách xử lý / quy trình đề xuất

1. Đọc `RULES.md` — component-first (không egui thô ở view).
2. Lấy spacing/radius/stroke từ `crate::tokens` / primitive re-export.
3. Lấy màu từ `theme.*` / `theme.semantic()` theo role (surface, border, accent, status).
4. Audit: grep literal trong `components/`; ưu tiên thay bằng token hoặc alias component config.

## Kiểm chứng

- **Lệnh:** `cargo test -p db-pro-ui` (hoặc module theme tests); visual matrix RQM L11 khi release.
- **Kỳ vọng:** Không thêm view-local color constant; light/dark cùng semantic role.

## Phương án thay thế và cạm bẫy

- Copy palette từ `theme-factory` skill **không** map qua semantic → vi phạm `.impeccable.md` principle 5.
- Sửa một call site thay vì shared component khi hai site lệch rhythm (xem `ui-consistency-audit` skill).
