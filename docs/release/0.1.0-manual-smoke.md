# DB Pro 0.1.0 — Manual Smoke Checklist

**Updated:** 2026-08-09  
**Estimated time:** 20–30 minutes  
**Prerequisites:** PostgreSQL instance, SQLite fixture, current Tauri build/dev runtime

> Run this checklist against the exact release candidate SHA. Do not mark a section complete from source review alone.

---

## Startup / Branding

- [ ] App launches from dock/taskbar/menu
- [ ] Splash screen appears with DB Pro branding
- [ ] Splash disappears and main window loads
- [ ] Dock/taskbar app icon is centered and visually correct
- [ ] No blank screen or frozen UI
- [ ] No console errors/panics on normal startup

## Connection — PostgreSQL

- [ ] Open Connection Dialog
- [ ] Fill PostgreSQL credentials
- [ ] Test Connection → success feedback
- [ ] Connect → Explorer loads schemas/tables
- [ ] Status bar shows connected state
- [ ] Disconnect → correct disconnected state
- [ ] Reconnect → Explorer reloads
- [ ] Bad password → useful error, no crash
- [ ] Bad host → timeout/error, no crash

## Connection — SQLite

- [ ] Open Connection Dialog → select SQLite
- [ ] Click Browse → native OS file picker opens
- [ ] Select `.db`, `.sqlite`, or `.sqlite3` → path populates field
- [ ] Cancel Browse → current field value is unchanged
- [ ] Connect → Explorer loads tables
- [ ] Query SQLite → results render
- [ ] Missing/invalid file → useful error
- [ ] No dialog plugin/permission runtime error

- [ ] Tables list under schema

- [ ] Empty schema shows a real empty state
- [ ] Long names truncate safely
- [ ] Right-click connection B → Refresh actually refreshes B, not active connection A
- [ ] Metadata refresh reflects a real schema change after refresh
- [ ] Single-click table → **Data preview**
- [ ] Single-click view → **Data preview**
- [ ] Double-click table → permanent Data tab
- [ ] Double-click view → permanent Data tab
- [ ] Repeated click/double-click does not duplicate the same resource tab
- [ ] Context menu Open Structure → Columns

- [ ] Data section renders rows
- [ ] Columns shows column info
- [ ] Indexes shows indexes

- [ ] DDL shows CREATE/inspection SQL

## Cancel / Execution Lifecycle

- [ ] Run long query such as PostgreSQL `SELECT pg_sleep(30)`
- [ ] Stop button cancels query

## Safety / Confirmation

Use disposable test objects only.

- [ ] Destructive SQL triggers confirmation before backend execution
- [ ] Reject confirmation → backend operation is not executed
- [ ] Confirm → operation executes or returns real DB error
- [ ] `DELETE` without safe predicate triggers destructive protection
- [ ] Read-only connection blocks update/delete/DDL at backend boundary

- [ ] Resize column; width persists for tab/resource state as expected

- [ ] Right-click cell → copy cell works

- [ ] Select a grid row

- [ ] Select text inside editor/input

## Data Grid — Staged Update Safety

Use a disposable table with a primary key and at least `name` + `age` columns.

### Multi-cell same-row composition

- [ ] Base row: `name=Alice`, `age=20`
- [ ] Edit `name` → `Bob`
- [ ] Edit `age` → `21` before Apply
- [ ] Change bar represents the row update without conflicting duplicate full-row snapshots
- [ ] Apply
- [ ] Reload row → **`name=Bob`, `age=21`**

### Latest value wins

- [ ] Edit `name` → `Bob`
- [ ] Re-edit same cell → `Charlie`
- [ ] Apply
- [ ] Reload → `name=Charlie`

### Delete supersedes pending update

- [ ] Stage an edit for one row
- [ ] Stage delete for the same row
- [ ] Only the delete intent remains for that row
- [ ] Apply after confirmation → row deleted

### Partial failure / retry

- [ ] Stage at least two independent row mutations
- [ ] Make one fail deliberately while another succeeds
- [ ] Successful revision disappears from pending changes
- [ ] Failed revision remains with error
- [ ] Retry Failed retries only failed revision(s)
- [ ] New pending work created after the original snapshot is not removed by old completion

### No-PK table

- [ ] Open table with no primary key
- [ ] Data is readable
- [ ] UI clearly explains editing is read-only because a primary key is required
