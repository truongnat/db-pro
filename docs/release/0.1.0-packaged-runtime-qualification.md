## 3. Platform-Specific Prerequisites & Environment Classifications

### 3.1 macOS (B1 — #91)
- **Target Arch**: `x86_64-apple-darwin` and `aarch64-apple-darwin` (Universal / Apple Silicon).
- **Environment**: Native AppKit / Metal acceleration supported. Headless CI runs execute complete non-interactive qualification suites (`cargo test --workspace`, release compilation).

### 3.2 Windows (B2 — #92)
- **Target Arch**: `x86_64-pc-windows-msvc`.
- **Environment**: Direct3D / DX12 / OpenGL via wgpu/eframe backend. Credential persistence maps to Windows Credential Manager (`wincred`).

### 3.3 Linux (B3 — #93)
- **Target Arch**: `x86_64-unknown-linux-gnu`.
- **Environment**: Wayland / X11 rendering via winit. Secret store utilizes D-Bus Secret Service with automatic in-memory / AES-GCM encrypted fallback when headless.

## 4. Triage Loop & Defect Classification Matrix (C1 — #94)

| Category | Definition | Action & Protocol |
| :--- | :--- | :--- |
| **P0 (Catastrophic)** | Data loss, corruption, security breach, launch panic | Immediate release block; invalidate current candidate SHA; patch code; rerun 100% test suites; re-freeze candidate. |
| **P1 (Core Failure)** | Provider correctness error, broken transaction, unsafe SQL | Blocking defect; create hotfix; verify provider integration; update test assertions; re-freeze. |
| **P2 (Non-blocking)** | Visual polish, minor latency, headless environment notes | Document in known limitations / release notes (e.g. HD-006 pg_restore version skew disclosure, HD-007 interactive GUI note). |
| **Environment Limitation** | Absence of display server / interactive window in CI | Classify as non-code limitation; qualify via comprehensive automated unit/integration suites + binary launch proofs. |
