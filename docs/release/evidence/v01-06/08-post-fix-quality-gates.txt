on first write. Flagged for the coordinator: a Finder-launched v0.1 build may be unable to
persist state. Fixing this means changing data-directory resolution (product behaviour), so
it is out of scope for this run.

--- 4.1 Archive determinism (honest limitation) ---
Two runs of package-linux.sh over the same binary produced different archive hashes
(eb8c4c41... then 6d02bb8f..., 7 bytes apart), because tar records member mtimes and the
bsdtar fallback does not sort or normalize them. The macOS archive has the same property.
The v0.1 contract (goal-3 section 15) requires a locked dependency graph, no floating git
dependencies and no network-fetched runtime assets — all of which hold — but it does NOT
claim bit-reproducible archives, and bit-reproducibility is not achieved here. Making the
macOS archive deterministic would need a fixed-mtime + sorted-traversal step; deliberately
deferred as out of scope for this run.

7. RISKS THAT CANNOT BE TESTED HERE (flagged for the CI run)
==============================================================================

WINDOWS (highest residual risk — script never executed on any Windows host):
  * PowerShell quoting: paths are passed as separate `-Parameter` values and joined with
    Join-Path; no string interpolation into a command line, but `-$env:APP_VERSION` style
    interpolation inside the pwsh step is untested. If it fails, it fails loudly.
  * `Compress-Archive -LiteralPath` with an array puts both files at the zip ROOT (no
    directory entries), which also sidesteps the Windows PowerShell 5.1 backslash-in-zip
    issue for nested paths. Untested here.
  * The PE machine-type check (`0x8664`) reads the header bytes directly; it is deterministic
    but has never run.
  * `build-output/db-pro-native.exe` uses forward slashes in a pwsh path — accepted by
    PowerShell, but unverified on the runner.
  * `ARCHIVE_NAME` is produced with `Split-Path -Leaf` so the bash assertion step never has
    to parse a Windows path (a `basename` on `D:\...` would have returned the whole string).
  * Line endings: the .ps1 is committed with LF. PowerShell 5.1/7 both accept LF. The repo
    has no .gitattributes forcing CRLF.

LINUX:
  * `file` must exist on ubuntu-latest for the arch assertion (`file` is preinstalled on
    GitHub's Ubuntu images; if it were missing the job fails on `file: command not found`
    rather than mislabelling — the failure mode is a hard stop, not a silent bad artifact).
  * The GNU-tar determinism flags are unverified on the runner (see section 4); the fallback
    path is functional, so this cannot fail the job.
  * `keyring`'s `sync-secret-service` requirement on Linux (risk register R002/R011) is
    unchanged and untested: the packaged Linux binary will need a D-Bus Secret Service
    provider at runtime.
  * The packaged binary has never been executed on Linux (no Linux host in this project).
    Windows/Linux remain BUILD_VERIFIED_VIA_CI at best, RUNTIME_UNVERIFIED.
