# Introspection IPC serialization contract tests (#72)

- Session: `v01-runtime` provider follow-up, 2026-09-15
- Tree: `main @ 0eb275e` (clean at the start of the change); fix commit recorded in `LEDGER.md`
- Issue: **#72** ([RC1][Introspection B1] Add explicit introspection IPC serialization contract tests) —
  parent workstream **#26**
- Boundary under test: the Tauri `introspect` command (`crates/tauri-app/src/commands/schema.rs:7`)
  serializes `IntrospectResultDto` (`crates/tauri-app/src/dto.rs:366`) as the IPC payload.

## 1. What existed before

No test serialized the introspection DTOs at all (`grep 'fn .*introspect'` over the tauri and native
crates found only the command and the runtime service — no shape test). The frontend that consumed this
boundary is archived (`_archive/README.md`: nothing there is built, tested or linted by CI; the
webview was superseded by the native egui UI), so the contract was pinned nowhere: a rename, a dropped
field, or the reintroduction of the old singular `fromColumn`/`toColumn` drift would have compiled and
shipped silently.

## 2. The contract tests

All in `crates/tauri-app/src/dto.rs` (tests module), built from one representative
`IntrospectResult` that exercises every DTO field — two tables (one with `row_count = None`), columns
with and without defaults, a single-column primary key, a composite primary key, an index, a
single-column FK, a composite FK (`order_id, product_id` → `id, product_id`), a view, and a trigger.

| Test | What it pins |
|---|---|
| `introspect_result_dto_serializes_the_locked_camel_case_shape` | the exact top-level key set (8 keys: `schemas`, `tables`, `columns`, `primaryKeys`, `indexes`, `foreignKeys`, `views`, `triggers` — sorted-compared, so an added *or* omitted field fails); camelCase leaf names (`rowCount`, `dataType`, `isPrimaryKey`, `tableName`, `defaultValue`, `functionDef`); `None` optional fields serialize as JSON `null` (`rowCount`, `defaultValue`) per the current contract |
| `introspect_result_dto_keeps_foreign_key_column_order_and_plural_names` | single FK `fromColumns`/`toColumns`; composite FK arrays keep provider order in both directions; `fromColumn`/`toColumn` keys must not exist |
| `introspect_result_dto_rejects_singular_foreign_key_names` | a payload carrying the pre-contract singular names does not pass the contract — the named drift has a red test |
| `introspect_result_dto_matches_the_checked_in_contract_fixture` | `serde_json::to_string_pretty` of the DTO is byte-identical to the checked-in fixture, so the fixture catches any shape change without manual reinterpretation |

**Checked-in fixture:** `crates/tauri-app/tests/fixtures/introspect-contract.json` (140 lines) — the
recorded whole-result shape. It was generated by serializing the actual DTO structs, then re-asserted
byte-for-byte by the last test above, so the fixture is emitted shape, not a hand-written copy.

**Mirrored consumer types:** the archived TypeScript mirror
(`_archive/frontend/src/modules/schema/types/schema.types.ts`) is consistent with the fixture (plural
`fromColumns`/`toColumns`, camelCase names; no singular drift) but is not part of any gate by design
(CI comment: `ci.yml:133-134`, "no Node/pnpm/TypeScript quality gate in this repository anymore").
The active consumer is the native UI (`map_schema_summary`, `crates/native-app/src/translate.rs:1245`),
which is covered by its own translation tests. CHECK payloads are deliberately absent from the fixture:
`IntrospectResultDto` carries no check-constraint field today and #68 is still open, matching the
issue's "CHECK payload only if #68 = KEEP".
