## What this document is and is not

**Is:** a description of the interface structure, labels, actions and layout constants that the
source code actually contains — enough for a reader to know what the app is supposed to show, and
enough for a later reviewer to know what to compare a real screenshot against.

**Is not:** a screenshot, a rendering, or a record of user-verified appearance. **Pixel-accurate
appearance has NOT been visually verified in this pass**: no spacing, colour, font, alignment,
clipping, overlap, z-order or DPI behaviour below has been seen. A layout declared in code can
still render wrong. Text extracted here is real (it is in the source), but that it *appears*
correctly on screen is unverified.

**Also not claimed:** any behaviour reachable only through interaction. Where a control's effect is
described, it is described from the code path that handles it, not from having clicked it. See
§17 for the full unverified list.

Citation convention: `crates/ui/src/<file>.rs:LINE` or a `:FROM-TO` range. Line numbers are from
`1a0c186`; after any edit to these files they will drift — cite the function name too.

## 1. Window composition

The root `update()` draws panels in this order, so this is the on-screen stacking and placement
(`crates/ui/src/app.rs:511-543`):

1. `draw_topbar` — a full-width top bar, exact height **38 px** (`navigation_view.rs:12-19`).
2. `draw_output_panel` — a bottom panel, only when open; default height from state, resizable
   within **120–420 px** (`navigation_view.rs:324-332`; constants `app.rs:166-167`).
3. `draw_statusbar` — a full-width bottom strip, exact height **28 px** (`navigation_view.rs:231-238`).
4. `draw_activity_bar` — a left rail, exact width **48 px**, not resizable (`navigation_view.rs:412-416`).
5. `draw_sidebar` — a second left panel, drawn only while `sidebar_open`; resizable, default width
   `max(state, 248 px)`, drag range **232–380 px**, clamped to **220–380 px** after layout
   (`navigation_view.rs:462-468, 691-696`; constants `app.rs:162-163`).
6. `draw_agent_panel` — a right panel, only while `agent_open`; resizable, **300–480 px**
   (`agent_view.rs:4-17`; constants `app.rs:164-165`).
7. The central panel — a frame filled with the `surface_app` token, containing the workspace
   (tab strip + active tab) (`app.rs:524-529`, `workspace_view.rs:544-556`).
8. Overlays, in this order: connection dialog, delete-connection confirmation, delete-folder
   confirmation, insert-row dialog, command palette, toasts (`app.rs:531-547`).

So the resting shape is: a 38 px top bar, a 48 px icon rail, a resizable sidebar, a tabbed
workspace, an optional right-hand Agent panel, a status bar, and an optional bottom output panel.

The window is forced to maximized for the first three frames of its life
(`app.rs:495-498`, `ViewportCommand::Maximized(true)`) — i.e. it opens full-screen, not at a
default 800×600.

## 3. Activity bar

A 48 px vertical rail, centered column of icon buttons, each 4 px apart, with the Settings button
pushed to the bottom (`navigation_view.rs:412-460`). From top to bottom:

| Icon | Tooltip | Activity / effect |
|---|---|---|
| `Database` | `Explorer` | `Activity::Explorer` — schema tree |
| `FileCode2` | `Queries` | `Activity::Queries` **and** switches the workspace to the Query tab |
| `History` | `History` | `Activity::History` — saved queries + local history |
| `Upload` | `Transfers` | placeholder pane |
| `Gauge` | `Monitor` | placeholder pane |
| `ArrowRightLeft` | `ER diagram` | `Activity::Diagram` **and** switches the workspace to the Diagram tab |
| `Bot` | `Agent (Copilot)` | toggles the right-hand Agent panel; note this entry has **no** activity, it is the only non-activity button in the rail |

(`navigation_view.rs:421-450`.) `Settings2` / `Settings` sits at the bottom
(`navigation_view.rs:452-457`). An entry is highlighted when its activity is active, **or** when
the Queries entry matches `WorkspaceTab::Query`, or when the Agent entry matches `agent_open`
(`navigation_view.rs:431-434`) — so the rail can show two entries lit at once (e.g. Queries + Agent).

The two placeholder activities render a centered icon, an uppercase title (`TRANSFERS`,
`MONITOR`), a `COMING SOON` badge, and a one-line description — "Background transfer jobs will
appear here when transfers are available." / "Connection health and query activity will appear here
when monitoring is available." (`navigation_view.rs:610-641`). These are honest empty states, not
hidden features.

## 4. Sidebar

### 4.1 Header row (every activity)

A connection/workspace selector on the left showing the active connection name (or `DB Pro` when
disconnected) followed by a small `ChevronDown`; clicking it opens the palette in Commands mode
(`navigation_view.rs:472-527`). On the right, two ghost icon buttons: `Search` (tooltip
`Search / Command Palette (⌘⇧P)`) and `Plus` (tooltip `New Connection`)
(`navigation_view.rs:529-552`).

### 4.2 Primary action

A full-width `New query` button, 30 px tall, hand-painted with a 6 px radius, a `SquarePen` glyph,
the label `New query`, and the shortcut `⌘N` right-aligned in muted text
(`navigation_view.rs:554-610`). It sits above a separator, then the per-activity content.

### 4.3 Explorer

A filter field with a `Search` glyph and hint `Filter objects…` occupying the available width,
followed by a `Plus` (`New connection`) and a `RotateCcw` (`Refresh active schema`, with a
right-click menu item `Refresh Schema`) (`explorer_view.rs:224-285`).

Empty state (no connections): a 28 px `Database` glyph, `No connections`, "Create a database
connection to begin.", and a `New connection` button (`explorer_view.rs:287-310`).

With connections, each connection is an expandable root row. Row state is conveyed by a status dot,
a badge, and dimming; a failed connection exposes its error message. Expansion defaults open when
the connection is connected or failed (`explorer_view.rs:312-345`). Expanding a connected
connection reveals:

- a **database node** (icon `Database`, accent-tinted, label = database name or `database` when
  empty) (`explorer_view.rs:481-518`);
- under it, **schema nodes** when the provider reports schemas (PostgreSQL), each a
  `Folder`/`FolderOpen` row tinted warm amber when it is the active schema and dimmed otherwise
  (`explorer_view.rs:536-600`); or, when there are no schemas (SQLite), the objects go straight
  under the database node (`explorer_view.rs:519-523`);
- a **`Tables` folder** (icon `Table2`, slate blue) with a right-side count, and a `4`-deep hint row
  reading `No tables in schema` / `No matching tables` when empty
  (`explorer_view.rs:660-720`). With a filter typed, the count renders as `matched/total`
  (`explorer_view.rs:668-673`).

A `matched/total` count and the `Filter objects…` field are the only search affordances in the tree.

### 4.4 Queries

`OPEN DOCUMENTS` section label with a `Plus` button, then one row per open query document; the row
title gains a trailing `•` when the document has unsaved changes; right-click offers `Duplicate
query` and `Close query` (the latter only when more than one document is open). A muted footer line
reads `Right-click a document for actions` (`navigation_view.rs:691-749`).

### 4.5 History

`Saved queries` (grouped by folder, collapsible, each group header showing `N queries`, with a
folder-level `Delete folder` context action and an empty state "No saved queries yet" / "Save a
query to keep it close at hand."), then a separator, then `Local history` as a reversed list of
executed queries, each showing its first line as the label (`navigation_view.rs:750-857`). Per-query
context actions: `Open in Editor`, `Copy SQL`, `Rename query`, `Delete query`
(`navigation_view.rs:822-838`). Deletion is confirmed inline with a warning-coloured
`Delete this saved query?` and `Confirm delete` / `Cancel` (`navigation_view.rs:840-857`).

### 4.6 Settings

Two cards (`navigation_view.rs:940-958`):

- **`APPEARANCE`** — a `Sun`/`Moon` glyph plus Light/Dark selectable values, the descriptive line
  "Quiet surfaces, violet focus states, and high-contrast data. The choice is saved locally.", and
  a `Reduce motion` checkbox with "Loading states keep a static status icon instead of a spinner."
  (`navigation_view.rs:960-989`).
- **`DATABASE FILES`** — backup/restore, gated on the provider's `backup` capability. When
  unsupported it shows "Backup and restore are unavailable for the active provider". Otherwise:
  a `Backup destination` field with hint `Choose a .sql backup path` plus `Choose path` and
  `Create backup`; and a `Restore from backup` field plus `Choose file` and `Restore database`,
  where restore raises an inline warning-coloured `Overwrite the active database?` with
  `Confirm restore` (danger button) / `Cancel` (`navigation_view.rs:941-1063`).

## 7. Query editor surface

Draw order inside the Query tab (`query_view.rs:9-38`): header → optional actions menu → optional
find bar → editor → floating completion popup → optional completion list → optional snippets →
diagnostics → output tabs → output pane.

**Header** (`query_view.rs:45-158`): the document title in subheading size, a `›`, a **connection
combo box** (selected text in accent colour) listing every connection, another `›`, and a **schema
combo box** (`main` for SQLite, `public` as the PostgreSQL fallback, otherwise the introspected
list). On the right: `Run` (primary, `Play`, tooltip `Run query (⌘↵)`) — which becomes `Stop`
(secondary, `Square`, `Stop query (Esc)`) while a cancellable query runs, or `Running…` (`Loader`)
when the provider reports no cancel support — plus a `MoreHorizontal` overflow button.

**Editor** (`query_view.rs:868-1000`): a custom SQL editor (`SqlEditor`) with a gutter, dialect-aware
tokenization (SQLite vs PostgreSQL chosen from the active driver), diagnostics, search highlighting,
an execution-range marker, and an inline AI prediction region. Editor height is clamped 260–360 px
when a result exists and 320–480 px otherwise.

**Actions** — `MoreHorizontal` menu (`query_view.rs:562-660`) and the editor-actions menu
(`query_view.rs:799-850`): `Format SQL` (`WandSparkles`), `Explain query`
(`ChartNoAxesCombined`), `Ask Agent` (`Bot`), `Save query`, `Save query as…`, `Find in SQL`
(`Search`), `Decrease`/`Increase font size` (`Minus`/`Plus`), `SQL completion` (`List`),
`Generate SQL Prediction` (`Bot`), `SQL snippets` (`FileCode2`), and `Export`.

**Find bar** (`query_view.rs:161-233`): a search field with `ChevronUp`/`ChevronDown` step buttons
and an `X` to close.

**Dialogs**: `Save query as…` (name/folder, `Save` + `Cancel`) (`query_view.rs:714-751`); a dirty-close
prompt with `Save` / `Don't Save` / `Cancel` (`query_view.rs:753-797`); an export dialog
(`query_view.rs:1290-1310`).

**Output tabs** (`query_view.rs:302-310`): `Results` (`Table2`), `Messages` (`MessageSquareText`),
`Explain` (`ChartNoAxesCombined`), `History` (`History`).

**Results pane** (`query_view.rs:390-438`): when a statement returns more than one result set,
`Result 1`, `Result 2`, … selectable labels appear; then a muted `N rows · N ms` line and an
`Export` button; then the grid, or a centered empty state `No results yet` / "Run a query to
populate this result grid."

## 8. Result grid

**Toolbar** (`result_grid_view.rs:693-750`) — a filter field hinting `Filter visible rows…` with a
clear `X`, a `N rows` badge, then `Copy Cell` (`Copy`), `Copy Row` (`Table2`), `CSV`
(`FileSpreadsheet`), `JSON` (`Braces`), a success badge for the last copy status, and a
right-aligned muted hint: "Double-click / Enter to edit · Right-click for actions · Drag divider to
resize" when editable, or "Click cell to select · Right-click for actions · Drag divider to resize"
when not. (For the table data editor this toolbar is replaced by §10's unified toolbar —
`result_grid_view.rs:84-88`.)

**Header** (`result_grid_view.rs:1873-2010`): a **48 px row-number gutter** (`app.rs:169`) whose
header cell contains `#` in monospace; then per column a **34 px** header cell with the column name,
its type, a sort marker (`↑` / `↓`, plus a priority digit for multi-column sorts), and **`PK` /
`FK` badges** (a `PK` badge drawn in `warning` on a 18 %-tint fill, `result_grid_view.rs:1991-2010`).
Each column's right edge is a **4 px drag target** for resizing — 3 px to either side of the border —
showing a horizontal resize cursor and a 2 px accent divider line while dragged
(`result_grid_view.rs:1917-1945`).

**Body** (`result_grid_view.rs:768-905`): rows are **28 px** tall; the gutter repeats the row number.
Error/selection/state is painted into the cell fill (`result_grid_view.rs:938-960`):

| State | Fill |
|---|---|
| edit validation error, or a failed cell mutation | `danger` at 14 % |
| conflict | `warning` at 16 % |
| row-level mutation error | `danger` at 8 % |
| selected row + selected cell | `accent` at 20 % |
| selected row, other cell | `accent` at 8 % |
| selected cell | `accent` at 14 % |
| staged (unsaved) row | `warning` at 12 % |
| hovered | `surface_hover` at 35 % |
| odd display position (zebra) | `surface_panel` at 25 % |
| even display position | `surface_elevated` |

Selected cells get a 1.5 px accent outline; error cells get a 1.5 px outline in `danger` or, for
conflicts, `warning`, with the message on hover (`result_grid_view.rs:964-1000`). Delimiters are
1 px `border_subtle` at 35 % — a continuous spreadsheet look with no outer frame around cells.

Cell context and copy actions are extensive: copy cell / row / rows with headers / rows as JSON /
rows as INSERT (`result_grid_view.rs:1535-1700`), `copy_row_as_json`, `copy_row_as_csv`,
`copy_all_as_csv`, `copy_all_as_json` (`result_grid_view.rs:1705-1800`). Column layout is
per-table and persisted: order, visibility, widths, plus `auto_size_column`,
`reset_grid_layout`, `move_column`, `hide_column`, `show_all_columns`
(`result_grid_view.rs:97-245`).

When a statement returns no columns, the grid is replaced by a centered `Statement completed` /
"This statement did not return any rows to display." state (`result_grid_view.rs:58-70`).

## 10. Table data editor

Entered by opening a table; the workspace shows a breadcrumb header and then a seven-tab bar
(`table_view.rs:139-270`).

**Breadcrumb header**: `Table2` glyph, connection name, `›`, schema, `›`, table name in subheading
size, an `N rows` badge from the table info, and on the right `Ask Agent` (`Bot`, opens the Agent
with "Explain the `schema.table` table and suggest queries"), `New Query` (`FileCode2`, prefills
`SELECT * FROM schema.table LIMIT 100;`), and `Refresh` (`RotateCcw`) (`table_view.rs:167-215`).

**Tab bar**: `Data` (`Table2`), `Structure` (`Columns3`), `Indexes` (`List`), `Foreign Keys`
(`ArrowRightLeft`), `Constraints` (`ShieldCheck`), `Dependencies` (`GitBranch`), `DDL` (`Code2`);
the selected tab's label is accent-coloured (`table_view.rs:225-258`).

**Data tab toolbar** — one unified row (`table_editor_view.rs:116-330`):

- `Refresh` (`RotateCcw`, tooltip `Reload table data (F5)`); refusing while changes are staged with
  the message "Apply or discard staged changes before refreshing";
- when mutable: `Add Row` (`Plus`), a warning line when the table has no primary key — "Table has no
  primary key; safe row editing is unavailable."; and once changes exist, a
  `N pending · +N ~N -N` button opening the pending-changes dialog, plus `Apply` (`Check`, tooltip
  `Apply all staged changes (⌘S)`) and `Discard` (`Undo2`, tooltip `Discard all staged changes (⌘Z)`);
- when not mutable but connected: `Read-only` in `warning`, or the no-primary-key text in `danger`;
- on failure: a `CODE · Mutation #N failed` line in `danger` with the message on hover, and buttons
  `Reload Row`, `Discard Local Change`, plus — for conflicts — `Resolve Conflict`
  (`GitCompare`, opens a 3-way panel) and `Retry`;
- a `N rows selected` badge when multi-select is active;
- a unified search/filter field with a column-scope combo defaulting to `All columns (Instant)`,
  and per-column filter operators scoped to the column's data type
  (`table_editor_view.rs:330-650`).

**Related dialogs**: insert-row dialog (`table_editor_view.rs:1009-1290`) with type-aware value
parsing and sample values (`table_editor_view.rs:699-965`); pending-changes dialog
(`:2000-2126`); conflict resolution with `Keep Mine` / `Use Database`
(`:2127-2430`); discard confirmation (`:1936-1999`).

**Canvas** (`diagram_view.rs:315-386`): a pannable, zoomable drawing surface on a grid backdrop

## 13. Agent panel (right side)

Header (`agent_view.rs:38-110`): `✨ Agent` in accent, a workflow-mode combo box with `Ask` / `Edit` /
`Agent` (disabled while a run is in flight), and on the right `Clear conversation` (`RotateCcw`),
`Close Agent` (`X`), and `Settings` (`Settings`, toggles an API-key form).

**The Preview badge** (`agent_view.rs:219-232`): the context strip shows `Preview` **only when
`agent_provider_label == "Offline draft"`** — i.e. when no provider key is configured and the app is
running its built-in offline responder. That provider declares itself
`AgentProviderKind::OfflineDraft`, `AgentProviderState::Preview`, detail "Pure Rust responder ·
writes stay unexecuted" (`agent.rs:75-88`). So the badge means "this is a preview provider, its
writes are not executed", not "the Agent feature is generally preview-stability". When a real
provider is configured, the badge is replaced by the provider label (`Groq`, `OpenAI` —

| `surface_panel` | `#f7f7f7` | `#2a2a2a` |

`theme.rs:56-95` (light) and `:97-136` (dark). Separate syntax tokens exist for keyword, string,
number, comment, type, function, operator, punctuation and variable, so the SQL editor's
highlighting is themed independently of the UI chrome (`theme.rs:21-40, 76-95`). Unit tests pin the
surface/accent values for both modes (`theme.rs:365-422`).

The scale is a 4 px grid with named spacing tokens, corner radii from 4–24 px plus a full pill,
a type scale from 11 px badges to 32 px display, icon sizes 12–24 px, strokes 1/1.5/2 px, motion
durations (80/140/180/200 ms, 5 s toast), and component sizes — button heights 28/36/42 px, input
heights 30/38 px, table row heights 32/40 px with a 36 px header, `TREE_ROW_HEIGHT` 28 px,
`SIDEBAR_ROW_HEIGHT` 32 px, `STATUS_BAR_HEIGHT` 26 px, `ACTIVITY_BAR_WIDTH` 48 px,
`TOOLBAR_HEIGHT` 38 px — all in `tokens.rs:9-158`.

`DbProTheme::apply` writes these into egui (`theme.rs:278-363`): window rounding 7 px, a window
shadow offset (0, 8) blur 24, `button_frame = false` and `collapsing_header_frame = false`
(controls opt into their own emphasis rather than every widget carrying an outline), `striped = true`,
selection fill `surface_active` with an accent stroke, and a deliberate note that "Selected rows/tabs
… stay neutral; blue is reserved for the interaction accent and the active indicator rather than
large fills" (`theme.rs:294-296`). Text styles: body/button 13, small 11, monospace 13
(`theme.rs:347-350`).

Fonts (`theme.rs:178-276`): the bundled Inter family (regular/medium, extended for Vietnamese
diacritics) registered as a custom `ui_medium` family used by the label/title helpers in
`tokens.rs:71-113`; a Lucide icon family; and a probed list of system UI and monospace fonts per
platform (SF/SF Compact/Segoe UI/DejaVu/Liberation/Noto/Arial; Menlo/Monaco/Cascadia/Consolas) with
Inter chained in as a fallback so full Unicode renders in monospace fields too.

Note: the Settings description string says "violet focus states" (`navigation_view.rs:978-982`)
while every accent token in `theme.rs` is blue. The description text appears to be stale copy; the
tokens are the authority for what is actually painted. Recorded as an observation, not a finding —
it needs a rendering to confirm either way.

## 20. Explicit non-claims

3. Any interactive behaviour: navigation, connection creation, query execution, editing, staging,

   what a reviewer must check; it does not close that gap. Closing it requires the runbook in
