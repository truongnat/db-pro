**Coverage vocabulary** (the issue's six words, used strictly):

| Word | Meaning here |
|---|---|
| `PROVEN` | source + automated tests + a CI job that runs them, all present at the baseline |
| `TESTED BUT NOT RELEASE-QUALIFIED` | automated tests exist and run in CI, but the release-critical path (packaged runtime, host interaction) is unverified — owner is the smoke runbook |
| `RUNTIME ONLY` | only the human smoke run can establish it; no automated coverage |
| `PARTIAL` | some layers covered, others not; the gap is named in the last column |
| `MISSING` | nothing covers it |
| `DEFERRED/NOT SHIPPED` | the capability is deliberately not in v0.1 (registry entry named) |

## Acceptance check

- **Every capability the issue lists has a row** (25 requested → 25 rows), and every row names either an
  evidence path or an explicit `DEFERRED/NOT SHIPPED` decision with its registry entry (LIM-012 import,
  LIM-016 workspace persistence, LIM-014 cancellation asymmetry).
- **No vague coverage claims:** each test cell names the test *and* the file:line it was read from; CI
  cells name the job and step; smoke cells name the runbook step of
  `docs/release/0.1.0-interactive-verification-runbook.md` (which #126 extended with Step 19).
- **The three release blockers that this map makes visible** are already tracked: `R-GUI-SMOKE`/`R-WINLINUX`
  (no window server, no Windows/Linux host) block every `RUNTIME ONLY` and `TESTED BUT NOT
  RELEASE-QUALIFIED` row from becoming `PROVEN`; the open defects #238, #243 and #244 are the only rows
  whose *automated* coverage is itself incomplete rather than merely unqualified.
- **For #111:** this is the per-capability evidence index it needs. Each row names the artifact a
  post-publish verification step has to re-open, and the release artifacts themselves are enumerated in
  `docs/release/evidence-manifest.json` (#88), which the same nine contract tests keep honest.
- **What this map does not claim:** a packaged runtime pass, a reviewer sign-off, or that a `PROVEN` row
  is release-ready — `PROVEN` here means the automated layers exist and run in CI at the baseline, not
  that the candidate was accepted.
