## P1 Release Blockers

### P1-1 — Current frontend full suite is not green/proven

The latest source commit `669d1fa` explicitly notes a pre-existing `tab-factories` test failure. Older verification (`1000/1000` at `92d9db9`) predates Wave A/B and is not release evidence for current HEAD.

**Required exit:**

```bash
cd frontend
npm ci
npm run typecheck
npm run lint
npm run test
npm run build
```

- Fix the `tab-factories` failure.
- Record exact Test Files / Tests / Passed / Failed at the exact release SHA.

### P1-2 — Release preflight format gate is unresolved

`.github/workflows/release.yml` runs `npm run format:check`. The previous verification report recorded 247 frontend files with Prettier drift, and there is no current release evidence that the whole checked tree now passes.

**Required exit:** `npm run format:check` must PASS at the release SHA, or the quality-gate policy must be deliberately changed and documented before release.

### P1-3 — Cross-platform Tauri artifacts not proven

The Release Build workflow is defined for macOS, Windows, and Linux, but the current SHA has no attached green release evidence/artifacts.

**Required exit:** successful release build jobs + artifacts for:
- macOS: `.app` / `.dmg`
- Windows: `.msi` / `.exe` (NSIS)
- Linux: `.deb` / `.AppImage` / `.rpm`

### P1-4 — Manual desktop runtime smoke not signed off

Source and unit tests cannot prove WebView/Tauri/OS integration.

**Required exit:** complete `docs/release/0.1.0-manual-smoke.md`, including:
- app launch/restart
- startup reconnect
- PostgreSQL good/bad credentials
- SQLite native Browse
- Explorer refresh
- table single click → Data preview
- table double click → permanent Data
- current/selection/all query execution
- Stop/Escape cancellation
- destructive confirmation/read-only block
- staged multi-cell update/delete behavior
- selected-row copy without hijacking cell editor/input copy
- workspace restore/no stale crash
