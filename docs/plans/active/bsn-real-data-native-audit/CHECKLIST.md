# BSN Real-Data Native Audit Checklist

Legend: `LIVE` = observed in native app on BSN; `OTHER-LIVE` = native UI runtime on a non-BSN provider; `API-LIVE` = successful BSN runtime/service evidence without native UI proof; `SYNTH` = deterministic presentation fixture only; `SRC` = source/test evidence only; `NOT VERIFIED` = no relevant evidence yet. A screenshot is required per feature row; one image may satisfy a row only if its feature/state is actually visible. Never treat synthetic or other-provider evidence as live BSN evidence.

## Gate 0 — Scope, source, privacy and connection safety

- [x] Record exact app/source SHA and binary build identity used for the run in `evidence/runtime/MANIFEST.md`.
- [x] Confirm the selected saved profile is `BSN` (no host/user/secret written to evidence).
- [x] Establish non-mutating session boundary; use metadata, bounded `SELECT`, and plain non-`ANALYZE` `EXPLAIN` only.
- [x] Prohibit writes, DDL, role changes, session termination, setting changes, task execution, restore and transfer apply.
- [x] Do not display or persist the one fetched BSN row; no raw row values entered logs or screenshots. Inspect sensitive columns before any future UI display.
- [x] Record data access / network / permission failures without retry loops or credential disclosure; safe runtime read paths succeeded.
