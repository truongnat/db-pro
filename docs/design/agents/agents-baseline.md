## Finding

DB Pro already has a typed, multi-step database Agent with bounded context/tool output, document-bound SQL patches, explicit confirmation, API-key storage through the runtime `SecretStore`, and canonical query/schema service reuse. This is a much larger capability than the Phase H and capability-matrix documents currently describe. No source-level P0/P1 was established in this read-only pass. Four P2 gaps need product/design disposition: `ExplainQuery` is allowlisted in Ask/Edit but then rejected by mode-level execution policy; provider egress disclosure omits some serialized context fields and endpoint overrides; workspace trust blocks a submit even though trusted file context is not included in the typed provider context; and AI capability/verification docs drift from the source and status correction.

## Surface, context, persistence, and providers

- Agent is a right-side panel toggled from the activity bar, rather than a central workspace activity (`crates/ui/src/app_lifecycle.rs:180-193,227-229`). UI presents settings, mode, context actions, tool activity and confirmation surfaces (`crates/ui/src/agent_view.rs:27-55`; `agent_surface_view.rs:137-159`; `agent_thread_surface_view.rs:145-223`). Modes are Ask/Edit/Agent; the default mode for a document without a session is Ask (`crates/ui/src/agent_actions.rs:118-141`). The view text maps these modes to Chat/Plan/Code (`crates/ui/src/agent_surface_view.rs:121-134`).
- Prompt submission requires a configured hosted provider and a current query document. It gathers document snapshot, connection ID/schema and schema-table metadata; typed `AgentContextBuilder` adds current SQL, user request, selected range, referenced tables, foreign keys, diagnostics and an optional result summary (`crates/ui/src/agent_actions.rs:67-79,118-179`; `crates/ui/src/agent_context.rs:27-99`; `crates/core/src/domain/agent_context.rs:112-145,166-227`). Context serialization is bounded by `MAX_AGENT_CONTEXT_CHARS = 12_000`; builder caps tables at 12, columns/table at 24, relations at 12 (`core/src/domain/agent.rs:7-18`; `core/src/domain/agent_context.rs:147-162,166-225`). Query-result samples are limited to 20 rows, 50 columns and 256 chars/cell; history/tool output/steps have their own caps (`agent.rs:7-18`; `agent_executor.rs:407-432`).
- Workspace-file trust check is active when `workspace_context_items` are present and the workspace is untrusted (`agent_actions.rs:67-73`). The typed provider run is built from the current query document, schema details and core `AgentContext`; that core context has no workspace-file field (`agent_actions.rs:143-179`; `core/domain/agent_context.rs:112-125`). Thus source shows the gate, but not file-content transmission through this workflow.
- Provider setup supports Groq and OpenAI by API-key prefix, uses Responses API defaults, requires an HTTPS endpoint, sends the key as Bearer auth, and sets `store: false` in request payloads. Requests have a 60-second timeout (`crates/runtime/src/agent.rs:13-20,127-183,190-210,225-260`). `DB_PRO_GROQ_ENDPOINT` / `DB_PRO_CODEX_ENDPOINT` can override default HTTPS endpoints; endpoint selection is configuration, not a fixed host allowlist (`agent.rs:134-152,163-183`). Provider inputs serialize the typed context and prompt, then append tool calls/results (`agent.rs:379-414`).
- Agent settings show provider configuration and egress disclosure, use a masked API-key input, clear the UI draft after open/close/save/forget, and expose an opt-in “Auto-run read-only queries in Agent mode” control (`crates/ui/src/agent_settings_view.rs:7-8,65-79,98-110,157-167`; `agent_state.rs:89-100`; `agent_events.rs:111-144`). Settings save/forget routes through runtime commands and runtime `SecretStore` methods (`runtime_protocol.rs:418-426`; `runtime/lib.rs:421-431`; `runtime/worker.rs:2593-2613`). `KeyringVault` tries the OS keyring and configured fallback stores; encrypted-file fallback is disabled by default in release builds and session fallback is in-memory (`infrastructure/src/secret/keyring_vault.rs:11-22,194-229`; `runtime/lib.rs:81-100`).

## Typed workflow and safety boundaries

- Eleven tools exist: InspectSchema/Table/Columns/ForeignKeys, GetCurrentQuery, PatchQuery, RunQuery, InspectQueryResult, ExplainQuery, SuggestIndexes and MonitoringRead (`crates/core/src/domain/agent.rs:220-235`; `crates/runtime/src/agent.rs:572-627`). Tools use canonical `SchemaApi`, `QueryApi` and `MonitoringApi`, not a parallel DB connection (`crates/runtime/src/agent_executor.rs:52-69,72-90,196-241,287-321`). MonitoringRead returns a bounded textual snapshot (counts plus up to eight active-query snippets); SuggestIndexes is metadata heuristic output, not DDL (`agent_executor.rs:243-285,287-321`).
- Ask allows read-style tools including ExplainQuery; Edit adds PatchQuery; Agent allows all tools (`crates/core/src/domain/agent_workflow.rs:541-570`). Workflow and executor both check tool permission (`agent_workflow.rs:337-385`; `agent_executor.rs:39-64`). Patch application checks document ID/version and UTF-8 range; UI applies only after explicit confirmation and runtime continuation revalidates the patch (`agent.rs:91-151`; `agent_workflow.rs:458-485`; `ui/agent_confirmation.rs:27-67`; `agent_orchestrator.rs:196-241`).
- RunQuery and ExplainQuery use SQL safety classification. Mutating/destructive/unknown statements require confirmation; auto-run applies only to read-only SQL in Agent mode when the explicit preference is on. The setting defaults false (`core/src/domain/agent.rs:375-412`; `agent_executor.rs:451-473`; `agent_workflow.rs:367-385`). The executor repeats the confirmation/mode guard and calls the shared Query API (`agent_executor.rs:196-230`). Confirmation is tied to run/document version and carries the immutable pending request; the orchestrator re-classifies RunQuery at approval and escalates if safety worsened (`agent_workflow.rs:388-409`; `agent_orchestrator.rs:120-194`).
- Runtime starts the provider/tool orchestrator from `StartAgentWorkflow`, retains paused runs while awaiting confirmation, and resumes via `ContinueAgentWorkflow` (`crates/runtime/src/worker.rs:1091-1179,1180-1247`). Orchestrator bounds steps, rejects call-ID collisions, and replays cached outcomes rather than re-executing matching calls (`crates/runtime/src/agent_orchestrator.rs:338-547`). Cancellation aborts the provider task and asks QueryApi to cancel the associated connection where applicable (`worker.rs:1248-1289`). UI event handling routes by document/session/run identity and drops stale/terminal events (`crates/ui/src/agent_events.rs:6-57`). Active-plan verification says provider/runtime evidence must still be re-established (see lifecycle section below).
